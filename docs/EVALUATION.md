# Evaluation

Every figure in this file is SINTETIS (synthetic data only, none from real documents). Templates and detectors have
the same author, so results lean optimistic.

## Random 16 digit strings that pass NIK validation (SINTETIS)

100,000 uniformly random 16 digit strings (SplitMix64, seed `0x5052494F52413131`, reference date 2026-11-25):
**2,761 pass (2.761 percent)**. Test: `empirical_random_16_digit_pass_rate` in `crates/privora-core/tests/nik.rs`,
which asserts a band of 2,500 to 3,000. Without a keyword, about 1 in 36 random 16 digit numbers is marked as a NIK
of medium confidence. This is the main false positive source of the NIK detector.

## Precision and recall (SINTETIS)

Generated by `make eval`: documents are regenerated from the seeds below, scanned (sensitivity SEIMBANG, reference
date 2026-11-25) and compared with the labels. 400 documents per seed, 8 templates. `make corpus` writes the same
documents as JSON Lines to `target/corpus/`.

- **Exact**: same kind and range. **Overlap**: same kind and the ranges intersect. **Gold fully covered by any
  finding**: every character of the true value lies inside some finding. This is the leak check.
- Rules were tuned on the development seed only. Regression thresholds in `tools/corpus-gen/tests/regression.rs` are
  the test seed values rounded down.

## Limitations

1. Templates and detector rules have the same author, so the numbers lean optimistic. Real documents have layouts,
   typos, OCR noise and phrasings that no template here has.
2. All values are invented. NIKs are built to pass the structure rules, so 100 percent NIK recall does not say that
   real NIKs are found.
3. No tables, multi column text, scanned text or mixed language documents.
4. Known weak spots: git remotes such as `git@host:org/repo.git` are reported as e-mail; Luhn valid random numbers as
   cards; a 16 digit number near a NIK, KTP or NPWP word becomes a low confidence finding; addresses are cut at 160
   characters; names without a label are never found.
5. Percentages on small categories have wide error bars.
